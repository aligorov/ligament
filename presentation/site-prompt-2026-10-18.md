10. **Notification Gateway и подтверждённые контакты** (Demo/Коммерция) — один вызов `POST /api/v1/notify` даёт мониторингу, ITSM и бизнес-системам доставку сотрудникам в их каналы (Telegram, eXpress, MAX, VK Teams, Slack, Mattermost, Discord, VK, Email, SMS, Voice); **динамияческие топики** и поддержка `image_url` на всём пути API → PWA → Telegram (готовые профили под Home Assistant, MikroTik, Frigate) с фильтром по топику в журнале и curl-примером в интерфейсе; endpoint привязан к пользователю только после подтверждения владения — через API нельзя отправить на произвольный адрес; согласие сотрудника по каждому каналу хранится на сервере; fan-out по всем включённым каналам, неизменяемый журнал доставки (кто/кому/каким каналом/статус) с фильтрами; политики retention и архивации сообщений; scoped API-токены, наследование CIDR-файрвола, fail2ban и аудита.

12. **Безопасность, роли, мониторинг, эксплуатация** — Argon2id для паролей, AES-256-GCM с AAD для секретов БД, Ed25519 для подписей лицензий, HKDF-SHA256 для ключей лицензионного манифеста, сравнения за постоянное время, fail-closed поведение при ошибке чтения лицензии; встроенный CIDR-файрвол и fail2ban; адаптивные политики (обязательные/запрещённые факторы по группам — «админам только passkey», временные окна, Geo-IP allow/deny; умная маршрутизация фактора по устройству); несколько каталогов AD/LDAP с виртуальным «главным» и входом `user`, `DOMAIN\user`, `user@domain`; роли admin / operator / auditor, scoped API-токены, impersonation с аудитом, break-glass коды; Prometheus `/metrics`, health-эндпоинт с версией сборки, SIEM-коннектор с шаблонами CEF/LEEF, вебхуки событий, алерты администраторам (лицензия/истекающие сертификаты/всплески ошибок); неизменяемый журнал аудита + CSV-экспорт + печатный **отчёт по инциденту**; фиксация внешнего и внутреннего IP при входе («из офиса» vs «из дома» различимо в уведомлении, push-карточке, аудит-UI, CSV и отчёте); корректный «реальный IP» за NAT (доверенные сети `proxy.trusted_networks` вместо «всего RFC1918»); принудительная политика 2FA — нельзя удалить единственный фактор; интерфейс и админка полностью локализованы на 8 языках (EN, RU, DE, FR, ES, PT, TR, ZH); админка без перезагрузки страницы (async-формы + toast-уведомления); карточка **«Версии и обновления»** — сравнение ядра, Relay и клиентов с Docker Hub и GitHub Releases + `GET /api/v1/app/version` показывает версии живых устройств, а не замороженные при регистрации; подсветка доступного обновления прямо в настройках клиента.
13. **Гостевой доступ** (Demo/Коммерция) — временные аккаунты подрядчиков, стажёров и посетителей для Wi-Fi, VPN и веб-порталов без создания постоянных учётных записей в AD; выдача сотрудником-спонсором (отдельный тумблер «спонсор гостей») и **поток «заявка гостя → одобрение → выдача пропуска»**, реквизиты показываются один раз; одноразовая ссылка для гостя; вход без онбординга — код по QR-приглашению или ссылке, без установки приложения; доступность отдельного приложения гостям — флаг «Доступно гостям»; гостевой VLAN; раздельные ограничения срока (время жизни аккаунта vs время сессии) и ревocation; все действия гостя атрибутированы спонсору в аудите; строгая изоляция группами и политиками — гость получает ровно разрешённое (например только гостевую SSID); SSO-вход гостям закрыт.
14. **Интеграция с СКУД (PACS) — ранний модуль** (бейдж `Ранний модуль`, отдельная лицензия) — подсистема `pacs` подключает системы контроля и доступа как источник событий физического присутствия: драйверы в реестре кода — **Болид** (интеграция через IntegrServ 2.0.1 JSON-RPC: live-webhook + опрос + удалённое открытие + health + каталог), **Болид — нативный MS SQL-адаптер** (обнаружение и опрос журнала; без удалённого открытия; DSN `sqlserver://`, принудительный `encrypt=true`), **Sigur**, **PERCo**, **Parsec**, **RusGuard** (опрос + удалённое открытие + health + каталог), плюс mock-драйвер для разработки; сопоставление карты сотрудника с учётной записью (ID, номер карты с сохранением ведущих нулей, табель, email, логин), поиск по всему справочнику (ФИО/ID/табель/email/логин), **автоматическая привязка по точно совпавшему нормализованному ФИО** (до 100 000 субъектов) с ручным unbind/rebind, **фоновый импорт справочника страницами по 500**, переживающий закрытие браузера и рестарт, автообнаружение оборудования и точек доступа, состояние присутствия по зонам (scoped по интеграции), журнал проходов с retention `pacs.retention_days` (по умолчанию 90 дней), фиксация госномеров (`Avto`), REST API + админка `/admin/pacs` со строгим лицензионным гейтом и fail-closed; **Zero-Trust проверка присутствия для RDP**: при политике цели `PACSPresence == "required"` перед claim-ом и повторно атомарно в SQL проверяется, что человек подтверждённо находится во внутренней зоне (state `inside`, reliability `reliable`, проход не старше 24 ч, свежесть данных по интервалу опроса, активная HA-lease). Обязательные честные сноски (см. раздел 12): приёмка подтверждена **на стенде**, проверка на реальном оборудовании в документации не зафиксирована; цена и модель продажи `pacs` в репозитории **не задокументированы** (только факт «строгий отдельный гейт, не входит в legacy/`all`/`*`); фича отсутствует в пользовательской документации.

## 10. Безопасность сайта (проверяемые требования)

1. **CSP** (в `<meta http-equiv>` и в `security-headers.conf`):
 `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src 'self'; font-src 'self'; connect-src 'none'; frame-ancestors 'none'; form-action 'self' https:; base-uri 'none'; object-src 'none'; upgrade-insecure-requests`
 `script-src 'self'` означает **ноль инлайн-обработчиков** (`onclick` запрещены, только `addEventListener` + делегирование). Если `connect-src 'none'` мешает решению — обосновать в отчёте, не ослаблять молча.
2. `security-headers.conf` — сниппет nginx: CSP (как выше), `Strict-Transport-Security: max-age=31536000; includeSubDomains`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), interest-topic-ads=()` (SOS — не в браузере сайта), `Cross-Origin-Opener-Policy: same-origin`, `Server` без версии.
3. **Ноль сторонних запросов**: ни шрифтов, ни CDN, ни аналитики, ни соцвиджетов, ни iframe (в том числе YouTube/Vimeo для видео — только локальные файлы в `assets/media/`; если ролики тяжелют — TODO в отчёт, не «вставить плеер»).
4. **Никаких форм с бэкендом и никакого сбора данных**: контакты — `mailto:` и copy-to-clipboard; ни `<form action>` на чужой домен, ни сторонних капч, ни `preconnect` наружу. Куки не используются; тема и язык — `localStorage` и обычные ссылки.
5. **JS-гигиена**: без `eval`, `new Function`, `innerHTML`/`outerHTML`/`document.write`, `insertAdjacentHTML`; данные манифеста только через `textContent` и `setAttribute`, имена файлов — относительные и с whitelist расширений (`.png .jpg .svg .webp .webm .mp4`). Сетевых вызовов (`fetch`/XHR/WebSocket) нет.
6. **Секреты и целостность**: не коммитить реальные IP/домены/имена заказчиков, `.env`, приватные ключи, живые Recovery Codes и подписанные лицензионные файлы; Activation Code и коды на скриншотах маскированы.
